# C1 トレーニングデータガバナンスとバイアスマネジメント

## 制御目標

トレーニングデータは、出自、セキュリティ、品質、公平性を維持する方法で調達、取り扱い、管理されなければなりません。これを行うことで、法的義務を果たすとともに、トレーニング中に現れる偏り、毒性、プライバシー侵害のリスクを低減し、AIライフサイクル全体に影響を及ぼす可能性を防ぎます。

---

## C1.1 トレーニングデータの出所

すべてのデータセットの検証可能なインベントリを維持し、信頼できるソースのみを受け入れ、監査可能性のためにすべての変更を記録してください。

|   #   | 説明                                                                                   | レベル | 役割  |
| :---: | ------------------------------------------------------------------------------------ | :-: | :-: |
| 1.1.1 | すべてのトレーニングデータソース（出所、管理者/所有者、ライセンス、収集方法、使用制限、処理履歴）に関する最新のインベントリが維持されていることを確認してください。   |  1  | D/V |
| 1.1.2 | トレーニングデータの処理で、不必要な特徴、属性、またはフィールド（例：未使用のメタデータ、機微なPII、リークしたテストデータ）が除外されていることを確認してください。 |  1  | D/V |
| 1.1.3 | すべてのデータセットの変更がログに記録された承認ワークフローの対象であることを確認してください。                                     |  2  | D/V |
| 1.1.4 | 可能な場合は、データセットまたはサブセットにウォーターマークやフィンガープリントが付与されていることを確認してください。                         |  3  | D/V |

---

## C1.2 トレーニングデータのセキュリティと完全性

トレーニングデータへのアクセスを制限し、保存時および転送時に暗号化し、改ざん、盗難、またはデータポイズニングを防ぐためにその完全性を検証します。

|   #   | 説明                                                                                     | レベル | 役割  |
| :---: | -------------------------------------------------------------------------------------- | :-: | :-: |
| 1.2.1 | トレーニングデータストレージおよびパイプラインがアクセス制御で保護されていることを確認してください。                                     |  1  | D/V |
| 1.2.2 | すべてのトレーニングデータへのアクセスがユーザー、時間、アクションを含めて記録されていることを確認してください。                               |  2  | D/V |
| 1.2.3 | トレーニングデータセットが、業界標準の暗号アルゴリズムとキー管理手法を用いて、転送中および保存時に暗号化されていることを確認してください。                  |  2  | D/V |
| 1.2.4 | トレーニングデータの保存および転送中に、データの完全性を確保するために暗号ハッシュまたはデジタル署名が使用されていることを確認してください。                 |  2  | D/V |
| 1.2.5 | トレーニングデータの不正な改変や破損を防ぐために、自動検出技術が適用されていることを確認してください。                                    |  2  | D/V |
| 1.2.6 | 廃止されたトレーニングデータが安全に削除または匿名化されていることを確認してください。                                            |  2  | D/V |
| 1.2.7 | すべてのトレーニングデータセットのバージョンが一意に識別され、不変に保存され、ロールバックおよびフォレンジック分析をサポートするために監査可能であることを検証してください。 |  3  | D/V |

---

## C1.3 トレーニングデータのラベリング品質、完全性、およびセキュリティ

ラベルを保護し、重要なデータには技術的なレビューを必須としてください。

|   #   | 説明                                                                                            | レベル | 役割  |
| :---: | --------------------------------------------------------------------------------------------- | :-: | :-: |
| 1.3.1 | ラベルアーティファクトの整合性と真正性を保証するために、暗号ハッシュまたはデジタル署名が適用されていることを検証してください。                               |  2  | D/V |
| 1.3.2 | ラベリングインターフェースおよびプラットフォームが強力なアクセス制御を実施し、すべてのラベリング活動の改ざん検知可能な監査ログを維持し、不正な変更から保護していることを確認してください。 |  2  | D/V |
| 1.3.3 | ラベル内の機密情報が保存時および転送時にデータフィールドレベルで抹消、匿名化、または暗号化されていることを検証してください。                                |  3  | D/V |

---

## C1.4 トレーニングデータの品質とセキュリティ保証

自動検証、手動スポットチェック、および記録された修正を組み合わせて、データセットの信頼性を保証します。

|   #   | 説明                                                                                                                                                                               | レベル | 役割  |
| :---: | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | :-: | :-: |
| 1.4.1 | 自動テストが、すべての取り込みや重要なデータ変換時にフォーマットエラーとヌル値を検出することを確認してください。                                                                                                                         |  1  |  D  |
| 1.4.2 | LLMのトレーニングおよびファインチューニングパイプラインが、ポイズニング検出およびデータ整合性検証（例：統計的手法、異常値検出、埋め込み分析）を実装し、潜在的なポイズニング攻撃（例：ラベルの反転、バックドアトリガーの挿入、役割切替コマンド、影響力のあるインスタンス攻撃）やトレーニングデータの意図しないデータ破損を特定していることを確認してください。 |  2  | D/V |
| 1.4.3 | 自動生成されたラベル（例：LLMや弱い教師あり学習によるもの）が、幻覚生成、誤解を招く、または低信頼度のラベルを検出するための信頼度閾値や一貫性チェックの対象となっていることを検証してください。                                                                                |  2  | D/V |
| 1.4.4 | リスク評価に基づき、生成された敵対的サンプルを用いた敵対的学習、摂動入力によるデータ拡張、またはロバスト最適化技術など、適切な防御策が関連モデルに実装され、調整されていることを確認してください。                                                                                |  3  | D/V |
| 1.4.5 | 自動テストが、すべてのインジェストまたは重要なデータ変換時にラベルのズレを検出することを確認する。                                                                                                                                |  3  |  D  |

## C1.5 データ系統とトレーサビリティ

監査可能性とインシデント対応のために、各データポイントの発生源からモデル入力までの完全な経路を追跡します。

|   #   | 説明                                                                                                  | レベル | 役割  |
| :---: | --------------------------------------------------------------------------------------------------- | :-: | :-: |
| 1.5.1 | 各データポイントの系譜（すべての変換、増強、統合を含む）が記録されており、再構築可能であることを確認してください。                                           |  2  | D/V |
| 1.5.2 | 系譜記録が不変であり、安全に保存されており、監査にアクセス可能であることを検証してください。                                                      |  2  | D/V |
| 1.5.3 | 系統追跡がプライバシー保護技術や生成技術を用いて生成された合成データをカバーしていることを確認し、すべての合成データがパイプライン全体で明確にラベル付けされ、実データと区別できるようにしてください。 |  2  | D/V |
