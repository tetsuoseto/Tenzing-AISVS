# C2 ユーザー入力検証

## 制御目標

ユーザー入力の堅牢な検証は、AIシステムに対する最も有害な攻撃のいくつかに対する第一の防御手段です。プロンプトインジェクション攻撃は、システム指示を上書きしたり、機密データを漏洩させたり、モデルを許可されていない行動に誘導したりすることがあります。専用のフィルターやその他の検証が導入されていなければ、研究ではコンテキストウィンドウを悪用したジャイルブレイクが引き続き有効であることが示されています。

---

## C2.1 プロンプトインジェクション防御

プロンプトインジェクションはAIシステムにおける最大のリスクの一つです。これに対する防御策は、パターンフィルター、データ分類器、および指示階層の強制を組み合わせて用います。

|   #   | 説明                                                                                                                                                                                                                                  | レベル | 役割  |
| :---: | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | :-: | :-: |
| 2.1.1 | ユーザープロンプト、RAG結果、プラグインやMCPの出力、エージェント間メッセージ、APIやWebhookの応答、構成ファイルやポリシーファイル、メモリの読み書きなど、動作を誘導する可能性のあるすべての外部または派生入力が信頼されていないものとして扱われ、引用またはタグ付けおよびアクティブコンテンツの削除によって無効化され、結合前または実行前に維持されたプロンプトインジェクション検出ルールセットまたはサービスによって精査されることを確認してください。 |  1  | D/V |
| 2.1.2 | システムが命令階層を強制し、システムメッセージおよび開発者メッセージがユーザーの指示やその他の信頼されていない入力よりも優先されることを、ユーザー指示の処理後でも検証してください。                                                                                                                                          |  1  | D/V |
| 2.1.3 | サードパーティのコンテンツ（ウェブページ、PDF、メール）から生成されたプロンプトが、メインプロンプトに連結される前に、単独でサニタイズされていることを確認してください（例えば、指示のような命令文の除去や、HTML、Markdown、スクリプトの内容の無効化など）。                                                                                               |  2  |  D  |

---

## C2.2 敵対的例耐性

自然言語処理（NLP）モデルは、人間が見逃しがちな微細な文字や単語レベルの摂動に対してまだ脆弱であり、モデルは誤分類しやすい傾向があります。

|   #   | 説明                                                                                                                                                      | レベル | 役割  |
| :---: | ------------------------------------------------------------------------------------------------------------------------------------------------------- | :-: | :-: |
| 2.2.1 | 基本的な入力正規化ステップ（Unicode NFC、相似字形のマッピング、空白のトリミング、制御文字および不可視Unicode文字の削除）が、トークン化または埋め込みの前、およびツールやMCP引数への解析の前に実行されていることを検証してください。                            |  1  |  D  |
| 2.2.2 | 統計的異常検出が、言語の規範から著しく離れた編集距離や異常な埋め込み距離を持つ入力を検出し、検出された入力がプロンプトへの連結やアクションの実行前にゲート処理されることを確認してください。                                                          |  2  | D/V |
| 2.2.3 | 推論パイプラインが、ハイリスクエンドポイントに対して敵対的トレーニングで強化されたモデルのバリアントや防御層（例：ランダム化、防御的蒸留、整合性チェック）をサポートしていることを確認してください。                                                      |  2  |  D  |
| 2.2.4 | 疑わしい敵対的入力が隔離され、完全なペイロードとトレースメタデータ（ソース、ツールまたはMCPサーバー、エージェントID、セッション）とともにログ記録されていることを確認してください。                                                            |  2  |  V  |
| 2.2.5 | 入力および出力におけるエンコーディングおよび表現のスマグリング（例：不可視のUnicode/制御文字、類似文字の置換、または混在方向テキスト）が検出され、軽減されていることを確認してください。承認された軽減策には、正規化、厳格なスキーマ検証、ポリシーベースの拒否、または明示的なマーキングが含まれます。 |  2  | D/V |

## C2.3 プロンプト文字セット

ユーザー入力の文字セットをビジネス要件に必要な文字のみに制限することは、さまざまな種類の攻撃を防ぐのに役立ちます。

|   #   | 説明                                                                                        | レベル | 役割  |
| :---: | ----------------------------------------------------------------------------------------- | :-: | :-: |
| 2.3.1 | システムがユーザー入力に対して文字セットの制限を実装し、業務上明示的に必要な文字のみを許可していることを確認してください。                             |  1  |  D  |
| 2.3.2 | 許可された文字セットを定義するために、許可リスト方式が使用されていることを確認してください。                                            |  1  |  D  |
| 2.3.3 | 許可されたセット外の文字を含む入力が拒否され、トレースメタデータ（ソース、ツールまたはMCPサーバー、エージェントID、セッション）とともにログ記録されることを検証してください。 |  1  | D/V |

---

## C2.4 スキーマ、タイプおよび長さの検証

不正な形式や過大な入力を特徴とするAI攻撃は、パースエラー、フィールド間でのプロンプト漏れ、リソース消耗を引き起こす可能性があります。決定論的なツール呼び出しを行う際には、厳密なスキーマの適用も前提条件となります。

|   #   | 説明                                                                                                                                                     | レベル | 役割  |
| :---: | ------------------------------------------------------------------------------------------------------------------------------------------------------ | :-: | :-: |
| 2.4.1 | すべてのAPI、ツール、またはMCPエンドポイントが明示的な入力スキーマ（JSONスキーマ、Protobuf、またはマルチモーダルの同等物）を定義し、余分なフィールドや未知のフィールド、暗黙の型変換を拒否し、プロンプトの組み立てやツール実行の前にサーバー側で入力を検証していることを確認してください。 |  1  |  D  |
| 2.4.2 | 最大トークン数またはバイト数の制限を超える入力が安全なエラーで拒否され、決して無言で切り捨てられないことを確認してください。                                                                                         |  1  | D/V |
| 2.4.3 | タイプチェック（例：数値範囲、列挙値、画像・音声のMIMEタイプ）がツールやMCPの引数を含め、サーバー側で強制されていることを確認してください。                                                                              |  2  | D/V |
| 2.4.4 | NLP入力を理解するセマンティックバリデーターが、定数時間で動作し、外部ネットワーク呼び出しを回避してアルゴリズム的なDoSを防止することを検証してください。                                                                        |  2  |  D  |
| 2.4.5 | 検証の失敗が、マスクされたペイロードのスニペットと明確なエラーコードでログ記録されており、セキュリティ対応を支援するためにトレースメタデータ（ソース、ツールまたはMCPサーバー、エージェントID、セッション）を含んでいることを確認してください。                             |  3  |  V  |

## C2.5 コンテンツおよびポリシースクリーニング

開発者は、不正な指示、ヘイトスピーチ、および/または著作権で保護されたテキストなどの許可されていないコンテンツを要求する、構文的に有効なプロンプトを検出できるようにし、それらが広がるのを防止する必要があります。

|   #   | 説明                                                                                                                                                           | レベル | 役割  |
| :---: | ------------------------------------------------------------------------------------------------------------------------------------------------------------ | :-: | :-: |
| 2.5.1 | コンテンツ分類器（ゼロショットまたはファインチューニング済み）が、暴力、自傷、ヘイト、性的内容、不法要求のすべての入力および出力をスコアリングし、閾値を設定可能であることを検証してください。                                                              |  1  |  D  |
| 2.5.2 | ポリシーに違反する入力は拒否され、それらが下流のLLMやツール／MCPの呼び出しに伝播しないことを確認してください。                                                                                                   |  1  | D/V |
| 2.5.3 | ユーザー固有のポリシー（年齢、地域の法的制約）を、エージェント役割属性を含むリクエスト時に解決される属性ベースのルールを通じて遵守していることを検証します。                                                                               |  2  |  D  |
| 2.5.4 | スクリーンログが、分類器の信頼度スコアおよび適用されたステージ（プリプロンプトまたはポストレスポンス）を含むポリシーカテゴリータグならびにトレースメタデータ（ソース、ツールまたはMCPサーバー、エージェントID、セッション）を含んでいることを検証し、SOCの相関分析および将来のレッドチームリプレイに備えること。 |  3  |  V  |

## C2.6 入力レート制限と乱用防止

開発者は、入力レートを制限し、異常な使用パターンを検出することで、AIシステムに対する悪用、リソース枯渇、自動化攻撃を防止すべきです。

|   #   | 説明                                                                                                                        | レベル | 役割  |
| :---: | ------------------------------------------------------------------------------------------------------------------------- | :-: | :-: |
| 2.6.1 | すべての入力およびツール/MCPエンドポイントに対して、ユーザーごと、IPごと、APIキーごと、エージェントごと、およびセッション/タスクごとのレート制限が適用されていることを確認してください。                         |  1  | D/V |
| 2.6.2 | バーストおよび持続的なレート制限がDoSおよびブルートフォース攻撃を防ぐように調整されていること、そしてエージェントの計画ループに対してタスクごとの予算（例えばトークン、ツール/MCP呼び出し、コスト）が適用されていることを確認してください。 |  2  | D/V |
| 2.6.3 | 異常な使用パターン（例：連続的なリクエスト、入力の過剰な送信、繰り返し失敗するツール/MCPコールや再帰的なエージェントループ）が自動的なブロックやエスカレーションを引き起こすことを確認してください。                      |  2  | D/V |
| 2.6.4 | 濫用防止ログが保存され、新たな攻撃パターンのために確認されていることを、トレースメタデータ（ソース、ツールまたはMCPサーバー、エージェントID、セッション）とともに検証してください。                              |  3  |  V  |

## C2.7 マルチモーダル入力検証

AIシステムは、注入、回避、またはリソースの乱用を防ぐために、非テキスト入力（画像、音声、ファイル）に対する堅牢な検証を含めるべきです。

|   #   | 説明                                                                                                                                                                          | レベル | 役割  |
| :---: | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | :-: | :-: |
| 2.7.1 | すべての非テキスト入力（画像、音声、ファイル）が処理前にタイプ、サイズ、フォーマットについて検証されていること、および抽出されたテキスト（画像からのテキスト変換や音声からのテキスト変換）や隠れたまたは埋め込まれた指示（メタデータ、レイヤー、代替テキスト、コメント）が2.1.1に従って信頼できないものとして扱われていることを確認してください。 |  1  |  D  |
| 2.7.2 | ファイルが取り込み前にマルウェアおよびステガノグラフィペイロードのスキャンを受けていること、またアクティブコンテンツ（スクリプトやマクロなど）が削除されるか、ファイルが隔離されることを確認してください。                                                                       |  2  | D/V |
| 2.7.3 | 画像/音声入力が敵対的摂動や既知の攻撃パターンについてチェックされていることを確認し、検出時にはモデル使用前にゲーティング（機能のブロックまたは低下）が行われることを確認してください。                                                                                |  2  | D/V |
| 2.7.4 | マルチモーダル入力検証の失敗がログに記録され、調査のためのアラートをトリガーし、トレースメタデータ（ソース、ツールまたはMCPサーバー、エージェントID、セッション）を含むことを確認してください。                                                                          |  3  |  V  |
| 2.7.5 | クロスモーダル攻撃検出が、複数の入力タイプにまたがる協調的な攻撃（例：画像内のステガノグラフィックペイロードとテキストのプロンプトインジェクションの組み合わせ）を相関ルールとアラート生成によって識別し、確認された検出がブロックされるか、もしくはHITL（ヒューマンインザループ）承認を必要とすることを検証する。                 |  2  | D/V |
| 2.7.6 | マルチモーダル検証の失敗が、すべての入力モダリティ、検証結果および脅威スコア、さらにトレースメタデータ（ソース、ツールまたはMCPサーバー、エージェントID、セッション）を含む詳細なログ記録をトリガーすることを確認してください。                                                          |  3  | D/V |

## C2.8 リアルタイム適応型脅威検知

開発者は、新しい攻撃パターンに適応し、コンパイル済みパターンマッチングによるリアルタイム保護を提供する高度な脅威検出システムをAI向けに導入すべきです。

|   #   | 説明                                                                                                                       | レベル | 役割  |
| :---: | ------------------------------------------------------------------------------------------------------------------------ | :-: | :-: |
| 2.8.1 | パターンマッチング（例：コンパイル済み正規表現）が、ツールやMCPの画面を含むすべての入力および出力に対して、遅延の影響を最小限に抑えて実行されることを検証してください。                                    |  1  | D/V |
| 2.8.3 | 適応型検出モデルが、最近の攻撃活動に基づいて感度を調整し、新しいパターンでリアルタイムに更新されることを確認し、リスク適応型の対応（例えば、ツールの無効化、コンテキストの縮小、またはHITL承認の要求）をトリガーすることを確認してください。 |  2  | D/V |
| 2.8.4 | ユーザー履歴、ソース、およびトレースメタデータ（ソース、ツールまたはMCPサーバー、エージェントID、セッション）を含むセッション行動の文脈分析を通じて、検出精度が向上していることを検証してください。                     |  3  | D/V |
| 2.8.5 | 検出パフォーマンス指標（検出率、誤検知率、処理遅延）が継続的に監視および最適化されていることを確認し、ブロックまでの時間および段階（事前プロンプト/応答後）を含めること。                                    |  3  | D/V |
