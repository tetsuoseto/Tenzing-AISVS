# C3モデルのライフサイクル管理と変更管理

## 制御目標

AIシステムは、許可されていないまたは安全でないモデルの変更が本番環境に到達するのを防ぐ変更管理プロセスを実装しなければなりません。この制御により、開発から展開、廃止に至るまでのモデルのライフサイクル全体を通じてモデルの整合性が確保され、迅速なインシデント対応が可能になり、すべての変更に対する責任が維持されます。

コアセキュリティ目標：整合性、追跡可能性、および回復性を維持する管理されたプロセスを採用することで、認可された検証済みモデルのみが本番環境に到達するようにすること。

---

## C3.1 モデル認証と完全性

検証された完全性を持つ認可済みモデルのみが、本番環境に到達します。

|   #   | 説明                                                                                                                                                                             | レベル | 役割  |
| :---: | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | :-: | :-: |
| 3.1.1 | すべてのモデルアーティファクト（重み、構成、トークナイザー、ベースモデル、ファインチューニング、LoRAのようなアダプター、およびセーフティ/ポリシーモデル）が認可されたエンティティによって暗号的に署名され、デプロイメントの許可時（およびロード時）に検証され、署名されていないまたは改ざんされたアーティファクトをブロックすることを確認してください。 |  1  | D/V |
| 3.1.2 | 依存関係の追跡がモデルレジストリおよび系統／依存関係グラフを通じてリアルタイムのインベントリを維持し、環境ごと（例：開発、ステージング、本番、リージョン）のすべての利用サービス／エージェントを特定可能な機械可読のモデル／AI部品表（MBOM/AIBOM）（例：SPDXまたはCycloneDX）を生成することを検証してください。           |  2  |  V  |
| 3.1.3 | モデルの起源の完全性とトレース記録に、認可機関の識別情報、トレーニングデータのチェックサム、合否ステータス付きの検証テスト結果、署名のフィンガープリント／証明書チェーンID、作成タイムスタンプ、および承認された展開環境を含めていることを確認してください。                                                |  3  | D/V |

## C3.2 モデル検証とテスト

モデルは展開前に定義されたセキュリティおよび安全性の検証を通過しなければなりません。

|   #   | 説明                                                                                                                                                                                                              | レベル | 役割  |
| :---: | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | :-: | :-: |
| 3.2.1 | モデルが導入前に、自動化されたセキュリティテスト（入力検証、出力のサニタイズ、安全性評価を含み、組織で事前に合意された合否基準を満たすこと）を受けていることを確認し、そのテストはエージェントのワークフロー（計画、ツールまたはMCPの呼び出し、RAG/メモリ、多モーダル）およびガードレール（ポリシー/安全モデルまたは検出サービス）を対象とし、バージョン管理された評価ハーネスで実施されていることを保証してください。 |  1  | D/V |
| 3.2.2 | すべてのモデル変更（展開、構成、廃止）が、不変の監査記録を生成することを検証してください。これには、タイムスタンプ、認証された実行者の識別、変更タイプ、変更前後の状態、トレースメタデータ（環境および利用サービス／エージェント）、およびモデル識別子（バージョン／ダイジェスト／署名）が含まれている必要があります。                                                     |  1  |  V  |
| 3.2.3 | 検証失敗が、文書化されたビジネス正当化を持つ事前指定された権限者からの明示的なオーバーライド承認がない限り、自動的にモデルのデプロイをブロックすることを確認してください。                                                                                                                           |  2  | D/V |

## C3.3 制御された展開とロールバック

モデルのデプロイメントは、制御され、監視され、かつ元に戻せるものでなければなりません。

|   #   | 説明                                                                                                                                                       | レベル | 役割  |
| :---: | -------------------------------------------------------------------------------------------------------------------------------------------------------- | :-: | :-: |
| 3.3.1 | 展開プロセスがモデルの起動または読み込み前に暗号署名を検証し、整合性チェックサムを計算することを確認し、不一致があった場合には展開を失敗させること。                                                                               |  1  | D/V |
| 3.3.2 | 本番環境へのデプロイメントが、事前に合意されたエラー率、レイテンシー閾値、ガードレール／ジェイルブレイクアラート、またはツール／MCPの故障率に基づく自動ロールバックトリガーを備えた段階的ロールアウトメカニズム（カナリアデプロイメント、ブルーグリーンデプロイメント）を実装していることを検証してください。 |  1  |  D  |
| 3.3.3 | ロールバック機能が完全なモデル状態（重み、構成、アダプターや安全性／ポリシーモデルを含む依存関係）を原子性をもって復元することを確認してください。                                                                                |  2  | D/V |
| 3.3.4 | 緊急モデルシャットダウン機能が、モデルエンドポイントを無効化し、エージェントツールまたはMCPアクセス、RAG/コネクター、およびデータベース/API認証情報、メモリーストアバインディングを事前に定められた応答時間内に非アクティブ化できることを検証してください。                      |  3  | D/V |

## C3.4 セキュア開発プラクティス

モデルの開発およびトレーニングプロセスは、侵害を防ぐために安全な手順に従わなければなりません。

|   #   | 説明                                                                                                                                                                  | レベル | 役割  |
| :---: | ------------------------------------------------------------------------------------------------------------------------------------------------------------------- | :-: | :-: |
| 3.4.1 | モデルの開発、テスト、および本番環境が物理的または論理的に分離されていることを確認します。これらは共有インフラストラクチャを持たず、異なるアクセス制御が適用され、データストアも隔離されています。また、エージェントのオーケストレーションおよびツールまたはMCPサーバーも隔離されています。                     |  1  | D/V |
| 3.4.2 | モデル開発の成果物（ハイパーパラメータ、トレーニングスクリプト、設定ファイル、プロンプトテンプレート、エージェントポリシー/ルーティンググラフ、ツールまたはMCP契約/スキーマ、アクションカタログまたは能力許可リスト）がバージョン管理に保存され、トレーニングに使用する前にピアレビューの承認を必要とすることを確認してください。 |  1  |  D  |
| 3.4.3 | モデルのトレーニングおよびファインチューニングが、出口許可リストを使用した制御されたネットワークアクセスを伴う隔離された環境で行われ、本番用ツールやMCPリソースへのアクセスがないことを確認してください。                                                              |  2  | D/V |
| 3.4.4 | トレーニングデータソースが、RAGインデックス、ツールログ、およびファインチューニングに使用されるエージェント生成データを含め、モデル開発に使用される前に整合性チェックを通じて検証され、信頼できるソースによる認証および記録された管理履歴を持っていることを確認してください。                            |  2  |  D  |

## C3.5 モデルの引退と廃止

モデルは、不要になったとき、またはセキュリティ上の問題が特定されたときには、安全に廃止されなければなりません。

|   #   | 説明                                                                                                                                                                                                                | レベル | 役割  |
| :---: | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | :-: | :-: |
| 3.5.1 | 退役したモデルのアーティファクト（アダプターおよび安全/ポリシーモデルを含む）が、安全な暗号消去を用いて確実に消去されていることを検証してください。                                                                                                                                        |  1  | D/V |
| 3.5.2 | モデルのリタイアメントイベントがタイムスタンプとアクターの識別情報、モデル識別子（バージョン／ダイジェスト／署名）、およびトレースメタデータ（環境および消費サービス／エージェント）とともにログ記録されていること、モデル署名が取り消されていること、さらにレジストリ／サービングの拒否リストおよびローダーキャッシュの無効化によってエージェントがリタイアされたアーティファクトを読み込むのを防いでいることを確認してください。 |  2  |  V  |
