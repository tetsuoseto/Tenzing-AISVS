# C2 Eingabevalidierung

## Kontrollziel

Robuste Validierung aller Eingaben ist eine Abwehrmaßnahme erster Linie gegen einige der verheerendsten Angriffe auf KI-Systeme. Prompt-Injection-Angriffe können Systemanweisungen außer Kraft setzen, vertrauliche Daten offenlegen oder das Modell in Richtung eines nicht zulässigen Verhaltens steuern. Ohne spezielle Filter und andere Validierungen zeigen Studien, dass Jailbreaks, die Kontextfenster ausnutzen, weiterhin wirksam bleiben. In agentischen und mehrstufigen Systemen tragen Eingaben von Tools, abgerufenen Dokumenten, Antworten des MCP-Servers und Ausgaben von Sub-Agenten dieselben Risiken wie direkte Benutzereingaben und erfordern dieselbe Validierungs-Pipeline. Dieses Kapitel konzentriert sich auf Bedrohungen, die für KI-Systeme einzigartig sind: Prompt Injection, Adversarial Inputs, die das Modellverhalten angreifen, KI-spezifische Content-Prüfung und Multi-Modal-Angriffsvektoren einschließlich adversarialer Perturbationen, steganografischer Payloads und Cross-Modal-Angriffen.

## C2.1 Abwehr von Prompt Injection

Prompt-Injection ist eines der größten Risiken für KI-Systeme. Abwehrmaßnahmen gegen diese Taktik nutzen eine Kombination aus Musterfiltern, Datenklassifizierern und der Durchsetzung von Anweisungshierarchien.

|   #    | Beschreibung                                                                                                                                                                                                                                                                                                                                                                                          | Ebene |
| :----: | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | :---: |
| 2.1.1  | Stellen Sie sicher, dass alle externen oder abgeleiteten Eingaben, die das Modellverhalten steuern können, als nicht vertrauenswürdig behandelt und von einem Prompt-Injection-Detektionsregelsatz oder -klassifizierer geprüft werden, bevor sie in Prompts aufgenommen oder verwendet werden, um Aktionen auszulösen.                                                                               |   1   |
| 2.1.2  | Verifizieren Sie, dass Eingabelängensteuerungen verhindern, dass benutzergesteuerte Inhalte einen definierten Anteil des Kontextfensters überschreiten, und dass Eingaben, die Token-Grenzen überschreiten, abgelehnt werden, statt stillschweigend abgeschnitten zu werden, sodass Systemanweisungen und Sicherheitsdirektiven nicht aus der effektiven Aufmerksamkeit des Modells verdrängt werden. |   1   |
| 2.1.3  | Überprüfen Sie, dass das System eine Zeichensatzbeschränkung für Benutzereingaben zu Modell-Prompts implementiert und nur Zeichen zulässt, die explizit für geschäftliche Zwecke erforderlich sind, wobei ein Allow-List-Ansatz verwendet wird.                                                                                                                                                       |   1   |
| 2.1.4  | Stellen Sie sicher, dass Prompts, die aus Inhalten Dritter (Webseiten, PDFs, E-Mails) stammen, isoliert bereinigt werden (z.B. das Entfernen anweisungsähnlicher Direktiven und das Neutralisieren von HTML-, Markdown- und Script-Inhalten), bevor sie an den Haupt-Prompt angehängt werden.                                                                                                         |   2   |
| 2.1.5  | Überprüfen Sie, dass das System pro Anfrage Grenzwerte für die Anzahl der vom Benutzer bereitgestellten Demonstrationen durchsetzt, die in einem einzelnen Kontextfenster enthalten sind.                                                                                                                                                                                                             |   2   |
| 2.1.6  | Stellen Sie sicher, dass das Prompt-Injection-Screening benutzerspezifische Attribute respektiert (z.B. Altersstufe, Berechtigungsrolle, regionale Content-Policy-Klassifizierung), indem attributebasierte Regeln, die zur Anfragezeit aufgelöst werden, angewendet werden, einschließlich der Rolle oder der Berechtigungsstufe des aufrufenden Agents.                                             |   2   |
| 2.1.7  | Überprüfen Sie, dass das System eine Anweisungshierarchie durchsetzt, in der System- und Entwicklernachrichten Benutzeranweisungen und andere nicht vertrauenswürdige Eingaben überschreiben, auch nachdem Benutzeranweisungen verarbeitet wurden.                                                                                                                                                    |   3   |
| 2.1.8  | Überprüfen Sie, dass die Anweisungshierarchie über mehrstufige Interaktionen und tool-unterstützte Workflows hinweg erhalten bleibt, einschließlich Prompt-Komposition und Zwischenoutputs, sodass benutzergesteuerte Inhalte System- oder Entwickleranweisungen nicht überschreiben können.                                                                                                          |   3   |
| 2.1.9  | Verifizieren Sie, dass das System Muster erkennt, die auf systematische Versuche einer zustandsgebundenen Verhaltensumgehung hinweisen, die mit vielen-Schuss-Jailbreaking übereinstimmen.                                                                                                                                                                                                            |   3   |
| 2.1.10 | Verifizieren Sie, dass erkannte In-Context-Verhaltens-Override-Versuche als Prompt-Injection-Ereignisse klassifiziert und behandelt werden.                                                                                                                                                                                                                                                           |   3   |

## C2.2 Vor-Tokenisierung Input-Normalisierung

KI-Modelle verarbeiten Text über Tokenizer und Einbettungen, die sich durch Kodierungstricks ausnutzen lassen, die für die herkömmliche Eingabevalidierung unsichtbar sind. Eine Normalisierung vor der Tokenisierung schließt Angriffsvektoren wie Homoglyphen-Substitution, das Einfügen unsichtbarer Zeichen und die Manipulation bidirektionalen Textes, die Standard-Allow-List-Filter umgehen, aber das Modellverhalten verändern. Für das Encoding-Smuggling auf der Output-Seite in modelgenerierten Inhalten, siehe C7.3.5.

|   #   | Beschreibung                                                                                                                                                                                                                                                                                                                                                        | Ebene |
| :---: | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | :---: |
| 2.2.1 | Stellen Sie sicher, dass die Vorverarbeitung der Eingaben (Unicode-NFC-Kanonisierung, Homoglyph-Zuordnung, Entfernung von Steuer- und unsichtbaren Unicode-Zeichen sowie Neutralisierung bidirektionaler Texte) angewendet wird, bevor tokenisiert oder eingebettet wird.                                                                                           |   1   |
| 2.2.2 | Prüfen Sie, dass Eingaben, die von irgendeinem Erkennungsmechanismus als adversarial identifiziert werden, vom Einbinden in Prompts oder von der Ausführung von Aktionen ausgeschlossen werden.                                                                                                                                                                     |   1   |
| 2.2.3 | Stellen Sie sicher, dass Eingaben, die nach der Normalisierung weiterhin verdächtige Kodierungsartefakte enthalten, abgelehnt oder zur Überprüfung markiert werden.                                                                                                                                                                                                 |   2   |
| 2.2.4 | Stellen Sie sicher, dass die Erkennung und Abwehr von Encoding- und Repräsentationsschmuggel in Eingaben erfolgt (z.B. unsichtbare Unicode-/Steuerzeichen, Homoglyphen-Umschaltungen oder gemischt ausgerichteter Text). Genehmigte Gegenmaßnahmen umfassen Kanonisierung, strikte Schema-Validierung, richtlinienbasiertes Zurückweisen oder explizites Markieren. |   3   |

## C2.3 Inhalts- & Richtlinienprüfung

Syntaktisch gültige Prompts können jedoch nicht erlaubte Inhalte anfordern, z. B. anweisungswidrige Inhalte gemäß Richtlinien, schädliche Inhalte oder eingeschränktes Material. Das Screening von Inhalten auf der Eingabeseite verhindert, dass solche Prompts das Modell erreichen.

|   #   | Beschreibung                                                                                                                                                                                                                                                                                                                                   | Ebene |
| :---: | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | :---: |
| 2.3.1 | Stellen Sie sicher, dass jede eingehende Eingabe von einem Content-Classifier hinsichtlich Gewalt, Selbstverletzung, Hass und sexualisierten Inhalten anhand konfigurierbarer Schwellenwerte bewertet wird, und dass Eingaben, die diese Schwellenwerte überschreiten, abgelehnt oder bereinigt werden, bevor sie den Modellkontext erreichen. |   1   |
| 2.3.2 | Stellen Sie sicher, dass die Klassifizierung von Prompt-Inhalten hinsichtlich missbräuchlicher Inhalte in nicht unterstützten Sprachen bewertet wird und dass erkannte Lücken durch ausgleichende Kontrollen wie Sprachenerkennung mit Ablehnung, konservative Schwellenwerte oder eine Weiterleitung zur manuellen Prüfung gemindert werden.  |   1   |
| 2.3.3 | Stellen Sie sicher, dass Eingaben, die Richtlinien verletzen, abgelehnt werden, sodass sie nicht an nachgelagerte Modell- oder Tool/MCP-Aufrufe weitergegeben werden.                                                                                                                                                                          |   1   |
| 2.3.4 | Stellen Sie sicher, dass Screening-Logs Klassifikator-Konfidenzwerte sowie Richtlinienkategorien-Tags mit dem angewendeten Schritt (pre-prompt oder post-response) und Trace-Metadaten (Quelle, Tool- oder MCP-Server, Agent-ID, Sitzung) enthalten, damit SOC-Korrelationen und zukünftige Red-Team-Wiederholungen ermöglicht werden.         |   2   |

## C2.4 Validierung von Multi-Modal-Inputs

KI-Systeme, die nicht-textliche Eingaben akzeptieren (Bilder, Audio, Video, Dateien), stehen vor einzigartigen Angriffsvektoren, bei denen bösartiger Inhalt modalitätsübergreifend eingebettet und in Text extrahiert werden kann, der den Kontext des Modells speist.

|   #   | Beschreibung                                                                                                                                                                                                                                                                                                                                                                                                                                 | Ebene |
| :---: | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | :---: |
| 2.4.1 | Prüfen, dass Text, der aus nicht-textlichen Eingaben extrahiert wird (z.B. image-to-text, speech-to-text), sowie versteckte oder eingebettete Inhalte (Metadaten, Ebenen, Alt-Text, Kommentare) als nicht vertrauenswürdig behandelt und gemäß 2.1.1 überprüft werden.                                                                                                                                                                       |   1   |
| 2.4.2 | Stellen Sie sicher, dass Bild-/Audioeingaben auf adversarische Manipulationen, steganografische Nutzdaten oder bekannte Angriffsmuster geprüft werden, und dass Erkennungen vor der Modellausführung eine Steuerung auslösen (blockieren oder Fähigkeiten einschränken).                                                                                                                                                                     |   3   |
| 2.4.3 | Verifizieren Sie, dass die Erkennung von Cross-Modal-Angriffen koordinierte Angriffe identifiziert, die sich über mehrere Eingabetypen erstrecken (z. B. steganografische Nutzdaten in Bildern kombiniert mit Prompt-Injection in Text), mithilfe von Korrelationsregeln und der Ereignisgenerierung von Alerts, und dass bestätigte Erkennungen blockiert werden oder eine HITL (Human-in-the-Loop)-Freigabe (human-in-the-loop) erfordern. |   3   |
