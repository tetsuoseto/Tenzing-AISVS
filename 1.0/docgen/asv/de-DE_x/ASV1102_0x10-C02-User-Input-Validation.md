# C2-Benutzereingabevalidierung

## Kontrollziel

Robuste Validierung von Benutzereingaben ist die erste Verteidigungslinie gegen einige der schädlichsten Angriffe auf KI-Systeme. Prompt-Injection-Angriffe können Systemanweisungen außer Kraft setzen, vertrauliche Daten preisgeben oder das Modell in ein Verhalten steuern, das nicht zulässig ist. Sofern keine speziellen Filter und andere Validierungsmaßnahmen vorhanden sind, zeigen Forschungen, dass Jailbreaks, die Kontextfenster ausnutzen, weiterhin wirksam bleiben werden.

>Anmerkung zum Geltungsbereich: Dieses Kapitel behandelt AI-spezifische Bedenken bei der Eingabevalidierung, die über eine allgemeine Eingabevalidierung hinausgehen. Standardmäßige Eingabevalidierung (Schema-Durchsetzung, Typprüfung, Zeichen-Allow-Listing, Ratenbegrenzung, Validierung von Datei-Uploads, serverseitige Durchsetzung, Protokollierung von Validierungsfehlern) wird in OWASP ASVS v5 in den Kapiteln V1, V2, V4, V5 und V16 behandelt und sollte als Grundlage implementiert werden. Dieses Kapitel konzentriert sich auf Bedrohungen, die für AI-Systeme einzigartig sind: Prompt Injection, adversarielle Eingaben, die auf das Modellverhalten abzielen, AI-spezifisches Content-Screening und Multi-Modal-Angriffsvaktoren.

## C2.1 Prompt-Injection-Abwehr

Prompt-Injection ist eines der größten Risiken für KI-Systeme. Abwehrmaßnahmen gegen diese Taktik nutzen eine Kombination aus Musterfiltern, Datenklassifizierern und Durchsetzung einer Anweisungs-Hierarchie.

|   #   | Beschreibung                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                     | Ebene |
| :---: | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | :---: |
| 2.1.1 | Stellen Sie sicher, dass alle externen oder abgeleiteten Eingaben, die das Modellverhalten steuern können, als nicht vertrauenswürdig behandelt und durch eine Prompt-Injection-Erkennungs-Regelsatz oder einen Klassifikator geprüft werden, bevor sie in Prompts aufgenommen oder verwendet werden, um Aktionen auszulösen.                                                                                                                                                                                                                                    |   1   |
| 2.1.2 | Überprüfen Sie, dass das System eine Anweisungshierarchie erzwingt, in der System- und Entwicklernachrichten Benutzernachrichten und andere nicht vertrauenswürdige Eingaben überschreiben, auch nachdem Benutzernachrichten verarbeitet wurden. Diese Durchsetzung muss über mehrstufige Interaktionen und tool-erweiterte Workflows hinweg erhalten bleiben. In solchen Fällen darf die Prompt-Zusammensetzung oder dürfen Zwischenoutputs nicht zulassen, dass benutzergesteuerte Inhalte System- oder Entwickleranweisungen beeinflussen oder überschreiben. |   1   |
| 2.1.3 | Stellen Sie sicher, dass Eingabelängen-Kontrollen verhindern, dass benutzergesteuerter Inhalt einen definierten Anteil des Kontextfensters überschreitet, und dass Eingaben, die Token-Grenzen überschreiten, zurückgewiesen werden, statt stillschweigend abgeschnitten zu werden, damit Systemanweisungen und Sicherheitsrichtlinien nicht aus der effektiven Aufmerksamkeit des Modells verdrängt werden.                                                                                                                                                     |   1   |
| 2.1.4 | Stellen Sie sicher, dass Prompts, die aus Inhalten Dritter (Webseiten, PDFs, E-Mails) stammen, isoliert bereinigt werden (zum Beispiel indem instruktionsartige Direktiven entfernt und HTML-, Markdown- und Skript-Inhalte neutralisiert werden), bevor sie an die Hauptaufforderung angefügt werden.                                                                                                                                                                                                                                                           |   2   |
| 2.1.5 | Überprüfen Sie, dass das System pro Anfrage die Grenzwerte für die Anzahl der vom Benutzer bereitgestellten Demonstrationen erzwingt, die in einem einzelnen Kontextfenster enthalten sind.                                                                                                                                                                                                                                                                                                                                                                      |   2   |
| 2.1.6 | Überprüfen Sie, dass das System Muster erkennt, die auf systematische Versuche einer gezielten Verhaltensüberschreibung im Kontext hindeuten, die mit vielen-Schuss-Jailbreaking übereinstimmen.                                                                                                                                                                                                                                                                                                                                                                 |   2   |
| 2.1.7 | Stellen Sie sicher, dass erkannte Versuche, verhaltensbezogene In-Context-Overrides zu erzwingen, als Prompt-Injection-Ereignisse klassifiziert und entsprechend behandelt werden.                                                                                                                                                                                                                                                                                                                                                                               |   2   |
| 2.1.8 | Stellen Sie sicher, dass das Prompt-Injection-Screening benutzerspezifische Richtlinien (Alter und regionale rechtliche Vorgaben) über attributbasierte Regeln respektiert, die zur Anfragezeit aufgelöst werden, einschließlich der Rolle oder der Berechtigungsstufe des aufrufenden Agents.                                                                                                                                                                                                                                                                   |   2   |
| 2.1.9 | Verifizieren Sie, dass das System eine Zeichensatzbeschränkung für Benutzereingaben in Modellaufforderungen implementiert, und lassen Sie nur Zeichen zu, die explizit für geschäftliche Zwecke erforderlich sind, unter Verwendung eines Allow-List-Ansatzes.                                                                                                                                                                                                                                                                                                   |   1   |

## C2.2 Vorverarbeitungs-Eingabenormalisierung (Pre-Tokenization)

KI-Modelle verarbeiten Text über Tokenizer und Embeddings, die sich über Kodierungstricks ausnutzen lassen, die für die herkömmliche Eingabevalidierung unsichtbar sind. Die Normalisierung vor der Tokenisierung schließt Angriffsvektoren wie die Homoglyphen-Substitution, das Einfügen unsichtbarer Zeichen und die Manipulation bidirektionaler Texte, die Standard-Allow-List-Filter umgehen, aber das Modellverhalten verändern.

|   #   | Beschreibung                                                                                                                                                                                                                                                                                                                                                                                                                  | Ebene |
| :---: | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | :---: |
| 2.2.1 | Stellen Sie sicher, dass die Eingabenormalisierung (Unicode NFC-Kanonisierung, Homoglyph-Mapping, Entfernung von Steuer- und unsichtbaren Unicode-Zeichen sowie Neutralisierung bidirektionalen Texts) angewendet wird, bevor eine Tokenisierung oder Einbettung erfolgt, und dass Eingaben, die nach der Normalisierung weiterhin verdächtige Kodierungsartefakte enthalten, abgelehnt oder zur Überprüfung markiert werden. |   1   |
| 2.2.2 | Stellen Sie sicher, dass vermutete adversarial Inputs in Quarantäne isoliert und protokolliert werden.                                                                                                                                                                                                                                                                                                                        |   1   |
| 2.2.3 | Überprüfen Sie, dass Encoding- und Repräsentations-Smudging in beiden Eingaben und Ausgaben (z. B. unsichtbare Unicode-/Steuerzeichen, Homoglyphen-Tausch oder gemischte Schreibrichtungen) erkannt und gemindert werden. Genehmigte Gegenmaßnahmen umfassen Kanonisierung, strikte Schema-Validierung, zustands-/richtlinienbasierte Zurückweisung oder explizites Markieren.                                                |   3   |

## C2.3 Content- und Richtlinienüberprüfung

Syntaktisch gültige Prompts können nicht erlaubte Inhalte anfordern, wie z.B. Richtlinien-verletzende Anweisungen, schädliche Inhalte oder eingeschränktes Material. Das Screening von Inhalten auf der Eingabeseite verhindert, dass solche Prompts das Modell erreichen. Informationen zur Filterung von Inhalten auf der Ausgabeseite finden Sie in C7.3.

|   #   | Beschreibung                                                                                                                                                                                                                                                                                                                    | Ebene |
| :---: | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | :---: |
| 2.3.1 | Stellen Sie sicher, dass ein Inhaltsklassifizierer jede eingehende Aufforderung auf Gewalt, Selbstverletzung, Hass, sexuellen Inhalt und illegale Anfragen bewertet, mit konfigurierbaren Schwellenwerten, bevor die Aufforderung in den Modellkontext aufgenommen wird.                                                        |   1   |
| 2.3.2 | Stellen Sie sicher, dass Eingaben, die gegen Richtlinien verstoßen, abgelehnt werden, sodass sie nicht an nachgelagerte Modelle oder Tool-/MCP-Aufrufe weitergegeben werden.                                                                                                                                                    |   1   |
| 2.3.3 | Stellen Sie sicher, dass Screening-Protokolle Klassifikator-Confidence-Scores sowie Policy-Kategorie-Tags mit der angewendeten Stufe (pre-prompt oder post-response) und Trace-Metadaten (Quelle, Tool oder MCP-Server, Agent-ID, Session) enthalten, um SOC-Korrelation und zukünftige Red-Team-Wiederholungen zu ermöglichen. |   3   |

## C2.4 Validierung von Multi-Modalen Eingaben

KI-Systeme, die nicht-textuelle Eingaben annehmen (Bilder, Audio, Video, Dateien), sind einzigartigen Angriffsvektoren ausgesetzt, bei denen bösartiger Inhalt über verschiedene Modalitäten hinweg eingebettet und in Text extrahiert werden kann, der den Kontext des Modells speist.

>Erläuterung zum Geltungsbereich: Die Standard-Validierung für Datei-Uploads (Typ, Größe, Format, Malware-Scans, Verhinderung von Pfad-Traversal) wird in OWASP ASVS v5 in Kapitel V5 behandelt und sollte als Baseline implementiert werden. Dieser Abschnitt adressiert KI-spezifische Risiken: das Extrahieren von Text aus nicht-textuellen Eingaben, die in Prompts einfließen, adversarielle Perturbationen, die die Modellwahrnehmung gezielt angreifen, sowie koordinierte Cross-Modal-Angriffe.

|   #   | Beschreibung                                                                                                                                                                                                                                                                                                                                                                                   | Ebene |
| :---: | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | :---: |
| 2.4.1 | Verifizieren Sie, dass Text, der aus nicht-textuellen Eingaben extrahiert wurde (z. B. image-to-text, speech-to-text), sowie aus versteckten oder eingebetteten Inhalten (Metadaten, Ebenen, Alt-Text, Kommentare) als nicht vertrauenswürdig behandelt und gemäß 2.1.1 geprüft wird.                                                                                                          |   1   |
| 2.4.2 | Überprüfen Sie, dass Bild-/Audio-Eingaben auf adversariale Störungen, steganografische Nutzdaten oder bekannte Angriffsmuster geprüft werden, und dass Detektionen das Gating auslösen (Blockieren oder Herabsetzen von Fähigkeiten) bevor das Modell verwendet wird.                                                                                                                          |   2   |
| 2.4.3 | Stellen Sie sicher, dass die Erkennung von Cross-Modal-Angriffen koordinierte Angriffe über mehrere Eingabetypen hinweg (z. B. steganografische Nutzdaten in Bildern kombiniert mit Prompt-Injection in Text) anhand von Korrelationsregeln identifiziert und Warnungen generiert, und dass bestätigte Erkennungen blockiert werden oder eine HITL- (human-in-the-loop) Genehmigung erfordern. |   3   |
